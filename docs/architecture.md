# Architecture

A modern rebuild of the original [`IEvangelist.PhotoBooth`](https://github.com/IEvangelist/IEvangelist.PhotoBooth) (2018, ASP.NET Core 2.1 + Angular 5 monolith) split into independently scaled, queue-decoupled components and orchestrated by .NET Aspire.

## Components

| Component | Tech | Path | Local URL |
|---|---|---|---|
| Aspire AppHost | TypeScript (`@aspire`) | `apphost.ts` | dashboard printed by CLI |
| Kiosk client | Angular 21, standalone, signals, zoneless | `apps/web` | http://localhost:4200 |
| API | ASP.NET Core minimal API, .NET 10 / C# 13 preview, SignalR | `apps/api` | http://localhost:5125 |
| Functions | Azure Functions v4, Node 20+, TypeScript | `apps/functions` | http://localhost:7071 |
| Storage emulator | Azurite (Aspire-managed container) | — | http://localhost:10000-10002 |

## End-to-end flow

```
[Kiosk]           [API]                 [stitch-gif]      [dispatch-sms]    [Azurite]
  │   POST /captures │                          │                  │                │
  │ ───────────────▶ │  blob: raw frames ─────────────────────────────────────────▶ │
  │                  │  table: capture row ───────────────────────────────────────▶ │
  │                  │  queue: stitch-requests ───────────────────────────────────▶ │
  │ ◀── 202 ──────── │                          │                  │                │
  │                  │                          │ ◀──── dequeue ─────────────────── │
  │                  │                          │  read frames ◀────────────────── │
  │                  │                          │  encode GIF (gifenc + pngjs)     │
  │                  │                          │  upload share GIF ─────────────▶ │
  │                  │ ◀── POST /internal/status (uploaded + shareUrl) ──         │
  │                  │  queue: sms-requests ──────────────────────────────────▶  │
  │ ◀── SignalR ──── │                          │                  │                │
  │                  │                          │                  │ ◀── dequeue ── │
  │                  │                          │                  │ provider.send │
  │                  │ ◀── POST /internal/status (sent) ────────────────────       │
  │ ◀── SignalR ──── │                          │                  │                │
```

## State machine

The capture row in Table storage is authoritative. State transitions are ETag-CAS guarded so duplicate queue messages cannot move the row backwards.

```
queued → stitching → uploaded → sending → sent
                        │           │
                        │           └─▶ sms_failed   (share URL still valid)
                        └─▶ stitch_failed             (hard error)
```

`StatusHub.JoinCapture(captureId)` always replies with the current Table snapshot before subscribing the caller to the live SignalR group, so a kiosk that joins late or reconnects still sees the correct phase.

## Idempotency

- **API → queue.** The API serializes queue messages with `JsonNamingPolicy.CamelCase` and base64-encodes the payload (Functions v4 default).
- **stitch-gif.** Short-circuits if the share blob already exists for the `captureId`. Cleans the raw-frame folder on success (best-effort).
- **dispatch-sms.** The API only enqueues `sms-requests` once when the capture row first transitions into `uploaded` with `SmsSentAt is null`.

## Webhook auth

Functions → API status webhooks are gated by an `X-Internal-Auth` header. The shared secret is generated by Aspire (`addParameterWithGeneratedValue("internal-webhook-secret")`) and injected as an env var into both the API and the Functions executable.

## SMS providers

Pluggable via `SMS_PROVIDER` env:

- `log` (default) — `LogSmsProvider` just logs the share URL. Lets the full flow run with **zero** credentials.
- `acs` — `@azure/communication-sms`, requires `ACS_CONNECTION_STRING` + `ACS_FROM_PHONE`.
- `twilio` — `twilio` npm, requires `TWILIO_ACCOUNT_SID` + `TWILIO_AUTH_TOKEN` + `TWILIO_FROM_PHONE`.
